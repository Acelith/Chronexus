# Chronexus 0.9.1 — Reliable backups and update announcements

Fixes an upgrade blocker for existing archives. SQLite retains the line endings of
its migration scripts, so an archive upgraded across Windows and Unix builds could
be rejected as having an unexpected database structure even though its tables and
constraints were identical. Backup verification now accepts equivalent SQL layout
while keeping quoted values, constraints, integrity, migration history and attachment
checks strict. The original archive is never replaced during backup.

Updates are checked once at **every app startup** when enabled. A successful check
in the previous 20 hours no longer suppresses the next launch. The herald still
waits until the app is idle, respects opt-out, ignored versions and reminders, and
never installs anything on its own. A manual update operation no longer consumes
and drops the startup check.

**For users blocked by the backup error in an older installed version:** that old
updater cannot repair its own backup code. Use this Windows x64 installer manually
after preserving a verified backup and closing Chronexus. Existing archives migrate
automatically on first open; do not delete, rebuild or edit your campaign database.
Schema remains 021; no new migration or campaign format is introduced by this fix.

Windows x64 app only, without AI weights or a Windows Authenticode signature.
The dedicated updater signature uses the existing production key. macOS, Linux,
ARM64 and an actual installation/upgrade are not verified for this hotfix.

Validation on Windows x64: 170 Rust tests, 179 frontend tests, TypeScript, ESLint,
Clippy, rustfmt, i18n check and Vite build. Mixed-line-ending schema 018/021 backups
restore and migrate automatically. Native WebView herald appearance, immediate
restart, reminder, focus and Axe checks passed on an isolated synthetic profile.
A verified read-only snapshot of the affected installed schema 018 archive also
migrated successfully on an extracted copy and remained backuppable afterward.
