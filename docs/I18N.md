# Current language policy — M26

English is the source, default and fallback language from source version 0.8.1.
Italian remains selectable and saved choices are preserved. An older archive
without an explicit language choice retains Italian through a one-time local
preference. Recovery is always **English · Reset language and script**.

Current catalogs include newly catalogued backend diagnostics. Coverage is shown
honestly per language: missing translations use English, not a fabricated complete
catalog. Italian aliases remain bundled for legacy diagnostic text and stable
message IDs. Machine translations still need native review. Original campaign
text and archived AI answers are never translated implicitly.

## Source code and tooling language

English is also used for internal label-map names (`appText`), code comments,
automated test descriptions, application diagnostics, generated readable-export
headings, future Logseq import reports, installer/setup messages and QA output.
Single-language desktop QA selectors follow the English interface; tests explicitly
selecting another locale retain the corresponding localized expectations.

Non-English text remains intentional in translation catalogs and native locale
names, Braille/lexicon mappings, multilingual search and instruction-risk detection,
legacy archived-answer sentinels, and synthetic campaign/Unicode fixtures. These
fixtures exercise preservation of original content; they are not untranslated app
labels. Storage identifiers, registered backup folders/prefixes, published package
names and historical commits are compatibility data and remain stable. Original
notes, source files, aliases, citations and saved language choices are never
translated implicitly. English export headings wrap the original content.

Current validation and platform limitations are recorded in [STATUS.md](STATUS.md).

## Writing modes

- **Italian non-contracted Braille**: literary six-point visual rendering, limited
  to letters, numbers, some accents and punctuation. It is not a complete
  typesetting or embossed printing engine and does not apply Braille codes of other languages.
- **International Morse**: Latin letters, numbers and supported punctuation.
  Decoding of dots/lines only produces uppercase; does not reconstruct accents
  or original uppercase. No automatic audio.
- **Minecraft Standard Galactic**: A–Z via glyphs U+EB40–U+EB59 of the font
  Monocraft, redesigned by the author and distributed under OFL license. Uppercase and
  lowercase share the symbol; digits and punctuation remain ordinary.

Non-representable characters remain original, with a warning in the laboratory.
App-controlled labels may show the transcription; editable fields,
native menus and critical messages may maintain ordinary text. Campaign content
is not transcribed or translated. Decorative representations
are `aria-hidden`; semantic text remains available to screen readers and
relative Braille peripherals. Hiding ordinary text does not remove its
accessible name. If the Galactic font does not load, normal text remains visible.

The **transcription laboratory** is separate from notes. The JSON v1 package
contains original, script and rendering: allows an exact restoration, verifying
consistency and version. This reversibility is not attributed to raw Morse.
No laboratory button applies the result to a campaign.

## Data, backup and network

`interface-preferences.json` v1 contains `locale`, `script` and `showOriginal`.
It is written atomically in the app's data root, outside of the restored
generations. A reading error allows startup in English and recovery
from the interface. Unknown values are rejected; external paths
are not accepted. No SQLite migration: **015** schema unchanged.

The global preference is not part of a campaign backup: a restore
maintains the language selected on the computer. Campaigns, documents, UUIDs, revisions,
manual labels, D&D sources, editions, and AI responses preserve the original texts.
Do not change `it.nodex.desktop`, `.nodex` extension, or preset normalization
to localize the interface. System file dialogs follow the OS language.

Catalogs, editor dictionaries, and fonts are included in the app. Changing the language
does not use Internet, Ollama, or a GPU. The initial preparation of translations used
**only static UI strings** with the already available local model
`qwen3:4b-instruct`: no reading or sending of campaigns, PDFs, or photos. This is a
development step, not an AI function executed at startup.

## Maintenance for developers and agents

1. Use `tr("English source text", [parameters])` for attributes, errors, and UI messages;
   `Text`/`Label` for labels that can have a decorative rendering. Keys
   Existing message IDs are preserved; new IDs use `m_` + the SHA-256 prefix of
   the English source. The scanner resolves existing English text to its stable ID.
2. Separate text and data. Do not pass to `tr` SQL, CSS selectors, URIs, classes, enums,
   IPC keys, UUIDs, Markdown, or user-inserted content. For native public diagnostics
   use `systemMessage` only in the UI rendering; unrecognized technical messages
   retain the original text. Maps of only
   labels use `localizeLabels`; persisted presets remain original data.
3. `pnpm i18n:scan` updates the candidate inventory. Review the diff: it is an
   assisted tool, not proof that every candidate is a UI string.
4. Update the catalogs. `scripts/i18n/translate-local.py` is optional and explicitly requires
   a pre-prepared local Ollama; it is not started by the build or app.
   Preserve `{0}`, `{1}` parameters, and attributions. New translations are drafts.
5. `pnpm i18n:normalize` applies the basic editorial lexicon in
   `scripts/i18n/core-labels.json`, removes obsolete keys, and unifies simplified Chinese
   with OpenCC, a development-only dependency. Do not modify user data.
6. `pnpm i18n:check`, `pnpm test`, typecheck/lint/format, and Rust checks before
   commit. Tests verify available translations, actual coverage, parameters, fallbacks,
   Arabic plurals, graph URIs, unchanged presets, preferences, and transcriptions.

Dates and numbers use Intl with reused formatters; search handles
plurals for the locale. Italian/German/French use Swiss formats, Brazilian Portuguese
and simplified Chinese are the agreed variants. Interpolated values
in Arabic are bidirectionally isolated; mixed content preserves the text.
The BlockNote dictionary is selected when opening the editor: switching from
settings uses SaveGuard, without remounting a still-dirty document.
